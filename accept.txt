一、网络编程基本概念
1、网络编程特点：
	本质还是进程之间的通信，只不过除了在同一平台，还可以跨平台通信(局域网中要求在同一网段下)
2、协议：
	在不同的计算机中，通信双方需要遵循同一个规则协议的模式
	TCP/IP协议：传输控制协议/因特网互联协议
	TCP：用于检查传输过程中的错误，传输一旦发生错误，就会停止传输直到安全为止
	IP：负责不同网络的数据交换
3、网络体系模型
	模型：指计算机内部的网络构造和网络协议
	用处：解析数据
	C/S模型：
		client/server模型，也就是客户端与服务器模型
		C/S模型是概念层面的，实现层面可以基于任何网络协议
		特点：
			客户端可以有多个，但服务器只有一个，属于一对多
			服务器拥有固定的IP地址和端口号，且始终处于运行状态
			服务器总是在等待客户端的链接，客户端可以随时访问服务器来获取服务
			服务器可以集中管理资源，有利于权限控制和系统安全
	
	B/S模型：
		B/S模型是一种以浏览器和服务器为核心的网络架构模型
		本质还是客户端/服务器模型，但在B/S模型中，将客户端运行在浏览器上，提高了系统的兼容性
		特点：
			B/S模型拥有良好的跨平台能力，用户可以在不同设备上访问同一个网站
			维护简单，只需要在服务器端对应的程序进行管理和维护即可，客户端不需要做过多的操作
			数据更安全，因为数据都保存在服务器端，即使客户端设备数据丢失，也可以通过其他设备恢复

	OSI模型：
		开放式系统互联，共分为7层
		应用层			老板说话
		表示层			秘书将老板说的话写成信
		会话层			前台将信塞到信封里，并附上对方的IP地址
		传输层			快递员拿到信，决定以什么方式去送信(TCP协议/UDP协议)
		网络层			快递员分析地址在哪里(IP协议)
		数据链路层		快递员规划好了路线
		物理层			快递员出发：网线、网卡
		OSI模型在发送时，数据从应用层出发，每经过一层，都会被封装上一层数据
		OSI模型在接收时，数据从物理层进入，每经过一层，就去掉一层的数据
		就像你在网上买东西一样，商家发货后，会给商品添加很多包装
		你收到快递后又要进行拆包，一层一层的剥开，拿出最里面的商品
	
	TCP/IP协议：
		将OSI模型浓缩成了4层
		应用层：将原先的应用层、表示层、会话层合一了
		传输层
		网络层 
		网络接口与物理层：原先的数据链路层和物理层

二、通信协议
1、TCP协议
传输控制协议 
特点：
	字节传输，速度相对UDP会较慢，但可以保证数据的安全
	面向连接，通信双方需要先建立连接才能进行数据传输
	可靠传输，一方收到对方数据，都会给对方发送回执确认
	数据无误，保证数据有序，不会重复发送，如果有数据丢失，会重新发送，如果网络拥堵会自动调节发送量
应用场合：
	传输质量要求较高，不能有数据丢失
	大数据量通信，以至于通信前后的连接和断开的开销可以忽略不计
	用户登入、账户管理、金融行业、、、
举个例子：
	tcp就像打电话，需要确保对方接听了才能进行通信


2、UDP协议
用户数据报协议
特点：
	数据报传输，速度相对TCP会更快
	面向无连接，通信双方不需要建立连接，可以直接给对方发送数据
	因为是无连接通信，所以可以给多个套接字发送消息
	可能会发生数据包丢失，收到数据后也不会给对方发生回执确认，不保证有序，丢失了也不会重发
应用场合：
	网络多媒体数据、直播
	适合与组播与广播
举个例子：
	UDP就像写信，不需要确保对方是否在，只要知道了地址就可以给对方写信
	
关于TCP的三次握手和四次挥手
术语：
	SYN：同步位，用于表示连接请求，一般为1
	seq：序号，一般是随机数
	ACK：确认位，为1表示确认有效，无值表示无效
	ack：确认号，在对方发送的序号基础上+1
	FIN：取消位，用于表示断开请求，一般为1
三次握手：
	首先客户端向服务器发送一个连接请求，并附上一个序号
	服务器接收到客户端发来的连接请求后，可以决定是否要建立连接
	如果服务器同意和客户端建立连接，就要给给客户端发送一个确认位，并附上一个确认号
	表示接收到了对方的请求，然后也给对方发送一个连接请求，并附上一个序号
	客户端收到服务器的连接请求后，先发送一个确认位和确认号，表示收到
	最后客户端再发送一个连接请求，这样客户端和服务器就成功建立了连接
四次挥手：
	首先客户端向服务器发送一个断开请求，并附上一个序号
	服务器接收到客户端发来的断开请求后，先发送回执确认
	然后再发送一个序号，用于询问对方是否认真的
	客户端收到后如果不对这个序号做回应，就表示默认了
	服务器再一定时间内如果没有收到刚才发送序号的确认回执
	那么服务器就会发送一个断开请求，并再次对之前的断开请求做确认回执
	客户端收到服务器发送的断开请求后，先做回执确认
	然后再次给服务器发送一个断开请求和序号
	这样客户端和服务器之间就断开了连接
TCP就是靠这个三次握手和四次挥手来保证连接和断开的安全性

三、专业术语
1、socket套接字
	网络编程有自己的API接口，可以创建不同的套接字
	根据需求来创建套接字，选择不同的协议创建
	套接字是特殊的文件描述符，也可以读取和写入数据
	套接字位于网络编程中的传输层和应用层

2、IP地址
	IP地址相当于一台主机的id，用来识别不同的计算机
	用户主机和其他主机之间的通信一般使用的都是IPv4地址
	IPv4地址采用4字节表示，每段都是1字节范围：0 ~ 255
	IPv4地址的表现形式被称为点分制，例如：192.168.14.91
	IP地址在形式上可以分为前后两段，前半段被称为网络号，后半段被称为主机号
	网络号作为当前主机所在网络的全世界范围内的唯一标识，主机号用来作为该主机在其所在网络内部的唯一标识
	可以将网络大致分为5类：
	A类地址：
		第一个自己为网络号，其他三个字节为主机地址
		1.0.0.1 ~ 127.255.255.255
		保留给政府
	B类地址：
		前两个字节为网络号，后两个为主机地址
		128.0.0.1 ~ 191.255.255.266
		分配给大型企业
	C类地址：
		前3个为网络号，最后一个为主机地址
		192.0.0.1 ~ 223.255.255.255
		民用
	D类地址：
		不区分网络号和主机号
		224.0.0.1 ~ 239.255.255.255
		用于组播网络
	E类地址：
		不区分网络号和主机号
		240.255.255.255 ~ 254.255.255.255
		用于实现
	网段：IP&子网掩码
	局域网内通信主机需要处于同一个网段内，默认网关一般是这个网络内路由器的IP地址
	DNS：域名解析服务器地址

3、端口号
	IP地址可以唯一识别一台计算机，但是一台主机上有不止一个进程
	所以为了区分一台主机上接收到的数据该交给哪个进程来处理
	就添加了端口号用来区分进程
	端口号占用2字节，取值范围：1 ~ 65535
	系统端口：1 ~ 1023
	注册端口：1024 ~ 49150(提供给软件注册使用)
	动态/私有端口：49151 ~ 65535
	注意：每次程序结束后要过一会再使用同一个端口号，因为动态分配的端口号在进程结束后会被回收
		  所以在回收期间，这个端口不能被分配
		  
4、字节序
	大端序：高地址存低位数据，低地址存高位数据
	小端序：高地址存高位数据，低地址存低位数据
	不管是什么平台，都属于本地字节序
	在网络上有专门的网络字节序，其实就是大端序
	本地字节序：跟平台有关
	网络字节序：固定是大端序
	在处理网络IP地址和端口号时要统一转换为网络字节序

四、UDP通信
UDP通信流程：
客户端：
	先准备有关邮箱(UDP套接字)
	写信，然后投递到邮箱中
	结束时记得关闭邮箱

服务器： 
	先准备有关邮箱(UDP套接字)
	绑定自己的IP地址和端口号
	从邮箱里收信
	结束时记得关闭邮箱
相关函数接口：
1、创建套接字
头文件：
	#include <sys/types.h>          /* See NOTES */
	#include <sys/socket.h>
函数原型：
	int socket(int domain, int type, int protocol);
参数：
	int domain：域
		AF_UNIX		本地协议，表示套接字只作用于本地通信
		AF_INET		网际协议，表示套接字可以通过IPv4地址进行网络通信
		AF_INET6	网际协议，表示套接字可以通过IPv6地址进行网络通信
	int type：类型
		SOCK_STREAM	数据流式套接字，用于TCP通信
		SOCK_DGRAM	数据报式套接字，用于UDP通信
	int protocol：协议，前面选择了网际协议和数据流/报式套接字，可以填0就行
返回值：
	成功：套接字
	失败：-1


2、绑定IP地址和端口号
函数原型：
	int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen);
参数：
	int sockfd：套接字 
	const struct sockaddr *addr：存放IP地址和端口号等信息的结构体的地址
	socklen_t addrlen：上面那个结构体的大小
返回值：
	成功：0 
	失败：-1
关于绑定用的结构体原型：
struct sockaddr {
	sa_family_t sa_family;	//协议，例如：AF_INET
	char        sa_data[14];//IP地址和端口号
}
问题：IP地址和端口号如何保存在一个数组中，每个数据又该如何保存？
解决：有个补丁，开发者添加了一个新的结构体类型，可以用这个结构体来保存数据，然后再强转为参数类型
新的结构体类型：
struct sockaddr_in {
	sa_family_t    sin_family; /* 协议: AF_INET */
	in_port_t      sin_port;   /* 端口号 */
	struct in_addr sin_addr;   /* IP地址 */
};
/* IP地址结构体原型 */
struct in_addr {
	uint32_t       s_addr;     /* 网络字节序的IP地址 */
};

3、将主机字节序转换为网络字节序的函数
头文件： 
	#include <arpa/inet.h>
函数原型：
h：host主机 	to		n：network网络
l：long32位		s：short16位
32位主机转网络字节序
	uint32_t htonl(uint32_t hostlong);
16位主机转网络字节序
	uint16_t htons(uint16_t hostshort);
32位网络转主机字节序
	uint32_t ntohl(uint32_t netlong);
16位网络转主机字节序
	uint16_t ntohs(uint16_t netshort);
参数：	
	要转换的数据
注意：IP地址不是用这些函数来转换，因为IP地址是点分制，不是一个整数
IP地址的网络和主机字节序转换函数：
头文件：
	#include <sys/socket.h>
	#include <netinet/in.h>
	#include <arpa/inet.h>
函数原型：
将字符串形式的点分制IP地址转换为网络字节序返回
	in_addr_t inet_addr(const char *cp);
将网络字节序的IP地址转换为字符串返回
	char *inet_ntoa(struct in_addr in);

4、发送数据
函数原型：
	ssize_t sendto(int sockfd, const void *buf, size_t len, int flags, const struct sockaddr *dest_addr, socklen_t addrlen);
参数：
	int sockfd：套接字
	const void *buf：要发送的数据 
	size_t len：要发送的字节数
	int flags：标志，填0就行
	const struct sockaddr *dest_addr：发送对象IP地址等信息 
	socklen_t addrlen：上面保存信息的结构体的大小
返回值：
	成功：发送的字节数
	失败：-1


5、接收数据
函数原型：
	ssize_t recvfrom(int sockfd, void *buf, size_t len, int flags, struct sockaddr *src_addr, socklen_t *addrlen);
参数：
	int sockfd：套接字 
	void *buf：保存接收到的数据 
	size_t len：要接收的字节数
	int flags：接收标志，填0就行
	struct sockaddr *src_addr：保存发送者的IP地址等信息 
	socklen_t *addrlen：保存了上面结构体大小的变量的地址
返回值：
	成功：接收的字节数
	失败：-1

6、关闭套接字
close(sockfd);
